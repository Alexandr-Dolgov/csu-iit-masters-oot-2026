# class03base. Паттерны создания и обёртки

Код к слайдам `slides/class03.md`, кроме слайдов про OrderFlow. Демо — тесты: каждый тест
показывает, что держится и что ломается. У слайдов внизу хэш коммита, `git checkout <hash>` —
состояние кода для слайда.

| Пакет | Что это |
|---|---|
| `creation` | Статические фабрики JDK (`List.of`, `Integer.valueOf`, `Optional.empty`); фабричный метод `Exporter.createFormatter`, `Collection.iterator`; абстрактная фабрика `DocumentBuilderFactory` |
| `singleton` | `Sequence.getInstance()` связывает тесты между собой; затем `Sequence` через конструктор, одиночка-`enum` без состояния, `Runtime`, `Collections.emptyList` |
| `adapter` | Адаптеры JDK: `InputStreamReader`, `Arrays.asList`, `Collections.list` |
| `decorator` | `InstrumentedHashSet extends HashSet` считает `addAll` дважды; декоратор `InstrumentedSet` через `ForwardingSet`; цепочка `java.io`; `Collections.unmodifiableList` |
| `proxy` | Кэширующий прокси `CachingPriceService`; динамический прокси `LoggingProxy` на `java.lang.reflect.Proxy` |
| `composite` | `Item` и `Bundle` под общим `Product`; JUnit `DynamicContainer` как компоновщик тестов |

## Тезисы:
* `new` всегда создаёт новый объект ровно названного класса; статическая фабрика может вернуть подтип,
  готовый объект из кэша, а ещё у неё есть имя
* Фабричный метод: скелет зовёт `createX()`, а какой продукт создать, решает подкласс; часто вызывается
  из шаблонного метода
* `Collection.iterator()` — фабричный метод: каждая коллекция создаёт свой итератор
* Абстрактная фабрика создаёт семейство согласованных объектов; клиент знает только интерфейсы
* Одиночка — это глобальное состояние: скрытая зависимость, тесты влияют друг на друга
* Сколько экземпляров нужно, решает тот, кто собирает приложение, а не сам класс; одиночка-`enum` —
  для объектов без состояния
* Адаптер: есть объект с одним интерфейсом, клиенту нужен другой
* Наследование нарушает инкапсуляцию: подкласс зависит от того, как родитель вызывает собственные методы
* Декоратор: тот же интерфейс плюс новое поведение, слои собираются в цепочку (`java.io`)
* Прокси: тот же интерфейс и контроль доступа к настоящему объекту — кэш, ленивость, права, журнал
* Декоратор и прокси устроены одинаково — различает их намерение
* Компоновщик: набор и элемент под одним интерфейсом, клиент их не различает

## Запуск

```shell
./mvnw -pl class03base test
```

Тесты запускаются и из IDEA: Run на классе или методе теста.
