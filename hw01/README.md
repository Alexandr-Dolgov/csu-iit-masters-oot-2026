## Задача 1. Тариф без `instanceof`

Общая для всех. Модуль `hw01OrderFlow`.

Сейчас знание о конкретном тарифе живёт за пределами тарифа:

```java
// ConsoleNotifier.orderPlaced
if (order.delivery() instanceof ExpressDelivery) {
    text += " Экспресс-доставка: привезём завтра.";
}

// SalesReport.render()
if (order.delivery() instanceof ExpressDelivery) {
    express++;
}
```

Новое требование логистики — **экспресс в день заказа**: класс `domain.SameDayDelivery`, 900 руб. при любой сумме,
срок 0 дней.

* Уведомление о новом заказе с `SameDayDelivery` заканчивается словами `Экспресс-доставка: привезём сегодня.`,
  с `ExpressDelivery` — по-прежнему `привезём завтра.`. У курьера и самовывоза обещания нет.
* В отчётах `экспресс: N` считает заказы и с `ExpressDelivery`, и с `SameDayDelivery`.
* В пакетах `app` и `infra` (кроме `app.Main`, где собирается приложение) не должно остаться упоминаний
  конкретных тарифов: ни `instanceof`, ни `switch` по типу, ни импортов.

Пример для заказа на 350 руб. с `SameDayDelivery`:

```text
[EMAIL anna@example.ru] Анна, заказ ORD-1 принят. Сумма: 1250.00 руб. Экспресс-доставка: привезём сегодня.
```

Над чем подумать: что сломается в вашем решении, если завтра появится «экспресс-самовывоз»? А тариф со сроком
2 дня, который маркетинг тоже хочет называть экспрессом? Чья это ответственность — текст «привезём сегодня»?


## Задача 2. Свой вариант: новый отчёт и новый статус

У каждого свой вариант — см. [VARIANTS.md](VARIANTS.md): номер в списке группы → часть А (отчёт) и часть Б (статус).
Модуль `hw01OrderFlow`. Задачу 1 лучше сделать раньше: `экспресс: N` в отчётах должен считать оба экспресса.

**Часть А** — новый формат отчёта. Подкласс `SalesReport` с именем из варианта и конструктором
`(OrderRepository orders)`. Точный ожидаемый вывод — в VARIANTS.md. Скелет `render()` можно (а в некоторых
вариантах нужно) расширить новыми крючками, но `render()` остаётся `final`, а `TextSalesReport` и `CsvSalesReport`
продолжают выдавать то же, что и раньше. Отчёт можно вызвать несколько раз — результат один и тот же.

**Часть Б** — новое правило жизненного цикла заказа. Новые методы `Order` и (если есть) сценарий в `app` — с именами
из варианта. Запрещённый переход — `IllegalStateException`, статус при этом не меняется. Статус заказа печатается
своим именем: `String.valueOf(order.status())` — `"DELIVERED"`, `"ON_HOLD"` и т. д.

Над чем подумать: сколько мест вы открыли, чтобы добавить статус? Что из этого можно было не открывать?
Нарушает ли ваш новый крючок или новый статус ожидания существующих клиентов `SalesReport` и `Order`?


## Задача 3. Банковский счёт

Общая для всех. Модуль `hw01bank`. Реализуйте методы, которые сейчас бросают `UnsupportedOperationException("TODO")`.
Сигнатуры публичных методов менять нельзя. Добавлять свои поля, методы, классы, интерфейсы -- можно.

* `Amount` — сумма в копейках. Значимый объект: неизменяемый, равенство по значению, отрицательной суммы не бывает.
* `Account` — счёт. Сущность: равенство по номеру `AccountId`, баланс меняется.
  Два вида: `Account.debit(id)` — баланс не бывает меньше нуля; `Account.credit(id, limit)` — баланс
  не бывает меньше `-limit`. `available()` — сколько можно снять прямо сейчас. Снять больше —
  `IllegalStateException`, баланс не меняется.
* `Command` (готов) — операция как объект: `execute()` и `undo()`. Реализуйте `Deposit`, `Withdraw`, `Transfer`.
  Перевод атомарен: и выполнение, и отмена либо меняют оба счёта, либо ни одного. Отмена пополнения, когда денег
  на счёте уже нет, — `IllegalStateException`, ничего не меняется. Перевод на тот же счёт —
  `IllegalArgumentException` в конструкторе.
* `Ledger` — журнал: `run` выполняет команду и запоминает её (если команда упала — не запоминает),
  `undoLast` отменяет последнюю (если отмена упала — команда остаётся в журнале), `size` — сколько можно отменить.

Начать можно с [`BankExampleTest`](../hw01bank/src/test/java/ru/csu/iit/master2026/oot/hw01bank/BankExampleTest.java):
снимите `@Disabled`, когда появится реализация, и допишите свои тесты.

Над чем подумать: напрашивается `class CreditAccount extends Account` — почему фабрики `debit` и `credit` вместо
наследника? Какой контракт `withdraw` должен быть записан у базового типа, чтобы кредитный счёт ему подчинялся?
