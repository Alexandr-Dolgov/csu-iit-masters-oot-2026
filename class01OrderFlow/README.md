# class01OrderFlow. Ответственность и абстракция на примере OrderFlow

Код к Части 2 слайдов `slides/class01.md`. История коммитов повторяет демо по шагам:
у слайдов внизу хэш коммита, `git checkout <hash>` — состояние кода для слайда.

Каждый шаг — рефакторинг, а не переписывание: новая абстракция появляется в `domain`
и в том же коммите её начинает использовать `legacy`. Вывод `legacy.Main` при этом
не меняется (кроме исправленного бага с деньгами). В коммите PlaceOrder пакет `legacy`
разбирается на `app` и `infra` и удаляется.

| Пакет | Что это |
|---|---|
| `legacy` | Стартовое состояние: `OrderService` на `String`/`double`, `Object[]` в `HashMap`, без тестов. С каждым коммитом тоньше, удалён в коммите PlaceOrder |
| `domain` | `Money`, `OrderId`, `Email`, `Customer`, `OrderItem`, тарифы доставки, `Promo`, `Order` |
| `app` | Сценарии `PlaceOrder`, `PayOrder`, `ShipOrder`, `CancelOrder`, отчёт `SalesReport`, порты `OrderRepository` и `Notifier`, `Main` |
| `infra` | `InMemoryOrderRepository`, `ConsoleNotifier` |

## Тезисы:
* Дизайн — это управление ценой изменения: сколько мест откроешь, чтобы выполнить требование
* Ответственность — это причина изменения: одна роль, по запросу которой класс меняют
* Деньги — не `double`: двоичная дробь теряет копейки
* Абстракция — решение о том, что скрыть (`Money`); выделить класс мало — его надо использовать
* Значимый объект (равенство по значению) и сущность (равенство по идентификатору)
* Примитивозависимость: типы вместо строк и параллельных массивов
* Тариф — объект, а не строка: стоимость и срок знает сам тариф
* Инкапсуляция — это не `private`, а невозможность нарушить инвариант (`List.copyOf`)
* Инварианты заказа: проверка в конструкторе и в единственной точке мутации
* Пять ролей — пять мест: домен, `Notifier`, `OrderRepository`, `SalesReport`, сценарии
* Зависимости через конструктор
* Новый тариф — новый класс: самовывоз без правки `Order`
* Связность и сцепление

## Для практики

`instanceof ExpressDelivery` остался в `ConsoleNotifier` (текст «привезём завтра») и в `SalesReport`
(число экспресс-заказов). Это знание о конкретном тарифе за пределами тарифа: что сломается,
если появится «экспресс в день заказа»?

## Запуск

Вывод `legacy.Main` на коммите legacy, деньги в `double`:

```text
Ошибка: оплата 3594.7 не совпадает с суммой заказа 3594.7000000000003
Заказов: 3, экспресс: 1, выручка: 62481.0 руб.
```

С коммита Money до коммита со статусами (`legacy.Main`) и на коммите PlaceOrder (`app.Main`):

```text
[EMAIL boris@example.ru] Заказ ORD-2 оплачен
...
Заказов: 3, экспресс: 1, выручка: 66075.70 руб.
```

С самовывозом (`app.Main`):

```text
[EMAIL anna@example.ru] Анна, заказ ORD-4 принят. Сумма: 3190.00 руб.
Заказов: 4, экспресс: 1, выручка: 66075.70 руб.
```

```shell
./mvnw -pl class01OrderFlow test                      # все тесты
docker compose run --rm --build class01orderflow      # app.Main
```

`legacy.Main` (на ранних коммитах) и `app.Main` запускаются и из IDEA: Run на методе `main`.
